# Tutorial para o Thomaz — Desenvolvendo a lojinha da Bull Racing com Claude

E aí, Thomaz! Bora responder sua pergunta com calma, porque dá pra fazer uma lojinha muito boa usando Claude do mesmo jeito que a gente fez a da Nupieepro, e o processo é mais simples do que parece.

## Como conseguir o Claude Code

Primeiro, sobre o "Code": o Claude Code é a ferramenta de linha de comando (CLI) da Anthropic que deixa o Claude trabalhar direto no seu projeto, lendo e editando arquivos, rodando comandos, criando commits e até subindo pull requests, em vez de você ficar copiando e colando código de um chat. Existem três formas de acessar ele. A mais simples, sem precisar instalar nada, é entrar em claude.ai/code pelo navegador e usar a versão web, que já roda um ambiente completo na nuvem — foi inclusive assim que este próprio tutorial foi escrito. Se preferir usar no seu computador, instale a versão de linha de comando com Node.js instalado rodando `npm install -g @anthropic-ai/claude-code` no terminal e depois digite `claude` para abrir a sessão interativa dentro da pasta do seu projeto; na primeira vez ele vai pedir pra você fazer login com sua conta Anthropic (`/login` dentro da sessão, ou ele abre o navegador sozinho pra autenticar). Também tem extensão pra VS Code e JetBrains, se você curtir trabalhar com editor gráfico do lado do terminal. Em qualquer um dos três casos, você precisa de uma conta Anthropic: dá pra usar um plano Claude Pro ou Max (que já inclui uso do Claude Code dentro da assinatura) ou configurar uma API key com faturamento via console.anthropic.com se quiser pagar por uso. Para times, dá pra convidar outras pessoas pra mesma organização e todo mundo usa a própria conta.

## Dicas pra desenvolver a lojinha

Pra estruturar o projeto, vale seguir o mesmo caminho que a gente usou aqui na Nupieepro: um site estático simples (HTML, CSS e JavaScript puro funciona muito bem e é fácil de hospedar de graça no GitHub Pages, Vercel ou Cloudflare Pages), com uma página pública de vitrine (tipo o nosso `index.html`) e uma página separada de administração protegida por login (tipo o nosso `admin.html`) pra cadastrar produtos, ver pedidos e gerenciar estoque sem mexer no código. Pro banco de dados e backend, o Supabase é uma ótima escolha porque é gratuito no plano inicial, dá autenticação pronta, e o Claude Code consegue conversar direto com ele através do MCP do Supabase, criando tabelas, rodando migrations e consultando dados sem você precisar sair do terminal. Antes de começar a pedir features, crie um arquivo `CLAUDE.md` na raiz do repositório contando pro Claude qual é a stack, as convenções de nome, como rodar o projeto localmente e regras de negócio importantes (tipo tamanhos de camisa, formas de pagamento, integração com WhatsApp pra confirmar pedido); isso evita ter que reexplicar o contexto toda sessão nova. Trabalhe em passos pequenos e incrementais — primeiro o catálogo de produtos, depois o carrinho, depois o checkout, depois o painel admin, depois PWA (manifest.json e service worker pra dar pra instalar a lojinha como app no celular) — testando no navegador a cada mudança em vez de pedir tudo de uma vez, porque fica muito mais fácil revisar o que foi gerado e corrigir rumo cedo. Use git desde o início: peça pro Claude criar branch, comitar com mensagens claras e abrir pull request pra cada funcionalidade, e sempre dê uma conferida no diff antes de aceitar, principalmente em telas de pagamento e no painel admin. Perto de colocar no ar, peça uma revisão de segurança focada em validar formulários, proteger as rotas de admin com autenticação de verdade e não deixar chave nenhuma (Supabase, gateway de pagamento etc.) exposta no código do front-end — só chaves públicas (anon key) podem ficar visíveis, o resto sempre fica em variáveis de ambiente do lado do servidor. Por fim, não tenha medo de pedir pro Claude explicar um trecho de código que você não entendeu, sugerir melhorias de UX pra deixar a identidade visual da Bull Racing em destaque, ou revisar o projeto inteiro de vez em quando pra simplificar o que ficou complexo demais — é basicamente ter um par de programação disponível 24 horas.
